# Сайт Елены Левошиной

Статический одностраничный сайт на React + TypeScript + Vite. Исходный объём работ — [DEVELOPMENT_PLAN.md](DEVELOPMENT_PLAN.md). Сейчас это **демонстрационная версия**: все контакты и объявления тестовые, портрет ожидается. Тестовые ссылки могут не работать; не используйте их для звонков и сообщений. Публикация реальных предложений требует замены данных и согласования владельца.

## Запуск и проверки

Нужен Node.js **22.23.3** (`.node-version`), npm 10.9.9. Совместимость проверяется по engines зависимостей. Node 22 находится в Maintenance LTS ([таблица Node.js](https://nodejs.org/en/about/previous-releases)); Vite требует Node 20.19+ / 22.12+ ([документация](https://vite.dev/guide/)).

```sh
npm ci
npm run dev
```

Открыть напечатанный локальный адрес. Сервер привязан к loopback. Для проверки сборки:

```sh
npm run check
npm run lint
npm run test:content
npm run test:images
npm run format:check
npm run build
npx playwright install --with-deps
npm run test:e2e
npm audit --audit-level=high
```

`dist/` — готовый статический сайт, Node на хостинге не нужен. `npm run preview` служит только локальной проверке. CI выполняет установку, проверки, сборку и Playwright в Chromium, Firefox и WebKit. Проверить ту же страницу за локальным HTTPS-контейнером можно командой `TEST_BASE_URL=https://localhost:18443 npm run test:e2e` (в этом тестовом режиме допускается внутренний сертификат). Эмуляция WebKit не заменяет Safari на iPhone. Результаты и ограничения фиксируются в [ACCEPTANCE.md](ACCEPTANCE.md).

Проверенные по npm registry 13.11.2026 версии: React/React DOM 19.3.1, Vite 8.3.8, React plugin 6.3.0, TypeScript 6.0.3 (совместим с typescript-eslint 8.72.2), ESLint 10.14.0, Prettier 3.10.1, Playwright 1.65.0, axe 4.14.0. Точные транзитивные зависимости — в `package-lock.json`. Образы Node 22.23.3-alpine и Caddy 2.11.9-alpine закреплены digest из Docker registry.

## Где менять контент

- `src/data/site.ts`: имя, телефон в международном формате и отображаемый номер, email, мессенджеры, часы, география, canonical origin и статусы согласования.
- `src/data/portrait.ts`: подготовленный портрет, импортированный как объект изображения.
- `src/data/services.ts`: услуги в согласованном порядке.
- `src/data/properties.ts`: десять демонстрационных объектов. Замените каждый настоящими данными; `demo: false` означает, что данные проверены. Не используйте вымышленные примеры как реальные предложения.
- `src/assets/`: локальные изображения, импортируемые из контентных файлов.

Снять объект с сайта: `published: false`. `id` сохраняйте постоянным: ссылка имеет вид `#object-demo-flat-001`. Поля зависят от типа: квартира — комнаты/этаж/этажность; участок — `landAreaM2`; коммерция — `purpose`. Цена в рублях, площадь в м², в интерфейсе участок переводится в сотки. Текст — без HTML. Несколько изображений раскрываются через нативный `details`, доступны клавиатурой, не прокручиваются автоматически. Каждому изображению нужны `alt`, реальные `width`/`height` и разрешение на публикацию. Удалите EXIF/GPS, подготовьте WebP/AVIF и подходящие размеры до добавления реальных фотографий. SVG в демонстрации — условная иллюстрация, не фотография объекта.

Основной контакт — звонок. Мессенджеры открываются обычными HTTPS-ссылками без отправки сообщения и без неподтверждённого предзаполнения. Формы, базы данных, аналитики, cookies, сторонних шрифтов и виджетов нет. Политика обработки данных должна соответствовать фактическим логам хостинга и выбранным сервисам; её содержание определяет владелец до публикации.

## Подготовка фотографий

Оригиналы храните вне репозитория и Docker context. Подготовка одного изображения:

```sh
npm run images -- --input /private/photos/flat.jpg --output src/assets/prepared/flat-001 --alt "Гостиная квартиры"
```

Команда создаёт JPEG/WebP/AVIF шириной до 480/800/1200 px без увеличения оригинала, применяет EXIF-ориентацию и удаляет EXIF/XMP/IPTC (включая GPS). Уже существующий каталог не перезаписывается. Внутри появится `image.ts`: импортируйте его в `properties.ts`, например `import livingRoom from '../assets/prepared/flat-001/image'`, затем используйте `images: [livingRoom]`. Для портрета импортируйте модуль в `portrait.ts` и экспортируйте его как `portrait` вместо `null`. Пересоберите сайт.

`ResponsiveImage` формирует picture/AVIF/WebP и JPEG srcset с sizes; портрет загружается с высоким приоритетом, остальные изображения лениво. Проверка контента сверяет существование вариантов, реальные размеры и отсутствие метаданных. Условный SVG демоверсии можно оставить до получения фото. После замены проверьте кадрирование лица и повторите измерения скорости.

`npm run test:images` проверяет EXIF-ориентацию, удаление метаданных, три формата и отсутствие увеличения на синтетической фотографии. `npm run assets` автоматически формирует локальную JPEG-картинку Open Graph; команды dev/build вызывают его сами. Для кириллицы используется шрифт из `build-assets/fonts/` с приложенной лицензией; шрифт нужен только сборке и не включается в runtime-образ.

## Подготовка публичного выпуска

1. Заменить тестовый номер, email, ссылки и домен `.invalid` на проверенные. Добавить портрет и реальные фото/объявления, удалить демонстрационные записи либо заменить их и снять флаг `demo`.
2. Получить согласие на материалы и адреса, подтвердить прямые контакты вместо формы (`directContactsApproved`), утвердить тексты и дизайн, заполнить `approved`.
3. Выполнить ручную приёмку: реальные устройства, экранный диктор, звонок и мессенджеры, документы, сведения владельца, права на фото.
4. Выполнить `npm run build:release`. Пока данные не готовы, команда должна завершаться ошибкой. Обычный `build` позволяет смотреть демоверсию с `noindex` и запретом в robots.txt.
5. Сверить метаданные в `dist/index.html`. Origin меняется только пересборкой. CSR не гарантирует индексацию: после публикации проверить отрисовку в поисковых инструментах.

## Docker / VPS

Production Compose использует заранее собранный образ; не выполняет сборку на VPS. На хосте нужны Docker Engine/Compose v2, доступный домен, A/AAAA и порты 80/443. AAAA добавляйте только при рабочем IPv6. При существующем reverse proxy адаптируйте порты/сеть и TLS, не запускайте два центра выдачи сертификатов.

```sh
# После замены и утверждения данных, из корня проекта:
git rev-parse HEAD
# Используйте полученный SHA вместо COMMIT_SHA, свой registry вместо registry.example.invalid.
docker build -t registry.example.invalid/realtor:COMMIT_SHA .
docker push registry.example.invalid/realtor:COMMIT_SHA
# Сохраните полученный digest и предыдущий выпуск.
```

Для локальной демонстрационной сборки допустим `docker build --build-arg BUILD_MODE=demo -t realtor:demo .`. Не размещайте этот образ публично.

На VPS скопируйте `compose.yaml` и `.env.example`, создайте `.env` с реальным `DOMAIN`, `ALIAS_DOMAIN` и `SITE_IMAGE` (лучше `registry/realtor@sha256:...`). Встроенный origin должен совпадать с DOMAIN. ALIAS_DOMAIN задаёт второе имя (например, www); DNS обоих имён должен вести на сервер. Caddy выпускает сертификаты для обоих имён и перенаправляет дополнительное на каноническое с сохранением пути и query.

```sh
docker compose config
docker run --rm -e DOMAIN=your-domain.ru --entrypoint caddy registry.example.invalid/realtor:COMMIT_SHA validate --config /etc/caddy/Caddyfile --adapter caddyfile
docker compose pull
docker compose up -d
docker compose ps
docker compose logs --tail=50 web
curl -I http://your-domain.ru/
curl -I https://your-domain.ru/
curl -I https://your-domain.ru/unknown-path
curl -I https://your-domain.ru/.env
```

Сборка создаёт `dist/security.caddy` с точным hash встроенного JSON-LD; Caddy импортирует его и запрещает HTTP-доступ к этому файлу. При переносе на другой статический хостинг настройте те же заголовки отдельно.

Caddy слушает 8080/8443 внутри контейнера; снаружи 80/443. HTTP/3 не включён. Работает UID/GID 10001, корневая ФС read-only, writable только volumes `/data`, `/config` и tmpfs `/tmp`. Проверка здоровья идёт на отдельный внутренний 8081. Проверить владельца volumes на реальном образе; не исправлять права широким `chmod 777`. Healthcheck не доказывает внешние DNS/TLS и не перезапускает unhealthy-контейнер.

Проверить редирект на единственный hostname, HTTPS, заголовки, CSP, 404 (с кодом 404), отсутствие исходников и `.env`, звонки и мобильную версию. Дополнительные домены перенаправляйте на канонический hostname на уровне DNS/прокси с корректным TLS. Access log не включён; Docker-логи ограничены 3 × 5 МБ. Ограничьте SSH ключами, проверьте firewall снаружи с учётом опубликованных Docker-портов. Сканируйте итоговый образ (`trivy image IMAGE`) перед выпуском.

## Обновление, откат и восстановление

После изменения контента повторить проверки и собрать новый образ с новым commit SHA. На VPS поменять только `SITE_IMAGE`, выполнить `pull` и `up -d`, проверить главную и изменённые объекты. HTML кешируется с revalidation, хешированные `/assets/*` — год. При пересоздании одного контейнера возможна короткая пауза; старые вкладки могут запросить старые ресурсы. При необходимости переносите ресурсы предыдущего выпуска в новый образ или обеспечьте окно совместимости на хостинге.

Откат: вернуть предыдущий digest в `.env`, повторить `docker compose pull` и `docker compose up -d`, проверить главную, контакты и ресурсы. Не удалять volumes сертификатов. База данных отсутствует, миграций нет.

Хранить удалённую копию Git, оригиналы фото, Compose/Caddy-конфигурацию, записи DNS, несколько предыдущих образов с lockfile/commit. Volume сам по себе не резервная копия. Данные Caddy резервировать согласованным способом при остановленном сервисе либо средствами согласованных снимков. Восстановление: чистый VPS → Docker/Compose → конфигурация и образ → DNS → запуск → внешняя проверка HTTPS. Репетировать на тестовом домене и staging CA, измерить время (ориентир до часа при доступном сервере и DNS). Для воспроизводимой локальной репетиции используйте `sudo bash scripts/test-container.sh realtor:demo PREVIOUS_IMAGE`: проверяются runtime/редиректы/headers, откат к переданному образу и восстановление из docker save/load с новыми volumes. Без PREVIOUS_IMAGE выполняется только запуск и восстановление. Все порты привязаны к loopback и выбираются Docker автоматически; ресурсы теста удаляются обработчиком EXIT, архив/журнал сохраняются в напечатанном каталоге /tmp. Этот тест не заменяет чистый VPS и публичный DNS/TLS.

Ежемесячно проверять зависимости, образы, свободное место, оплату домена/VPS, контакты и актуальность объектов. Исправления безопасности выполнять по риску раньше графика. Никогда не помещать токены/пароли в исходники, публичные env или образ.
